# ตั้ง staging สำหรับทดสอบแจ้งเตือน — คู่มือสำหรับเจ้าของ (ไม่ต้องเขียนโค้ด)

> **ยังไม่ต้องทำตอนนี้ก็ได้** — นี่คือลำดับขั้นเมื่อพร้อมทดสอบบนมือถือจริง
> ⚠️ ทุกขั้นในหน้านี้ **แยกจากของจริงทั้งหมด** ร้านยังทำงานปกติระหว่างทำ
> ⚠️ **ห้ามเอา credential ของ ZORT / LINE / ชีตจริง ใส่ในโปรเจกต์ทดสอบเด็ดขาด**

---

## ภาพรวม — ต้องมี 4 อย่างที่ "แยกจากของจริง"

```
1. ชีตทดสอบ      = ก๊อปชีตจริง 1 ใบ            (ข้อมูลปลอม แก้พังได้)
2. GAS ทดสอบ     = Apps Script โปรเจกต์ใหม่     (ชี้ไปชีตทดสอบ · ไม่มี ZORT/LINE · ไม่มี trigger)
3. Firebase ทดสอบ = โปรเจกต์ใหม่                (ไว้ส่งแจ้งเตือน)
4. เว็บทดสอบ      = ลิงก์ preview ของ Cloudflare (คนละลิงก์กับของจริง)
```

---

## ขั้นที่ 1 — ชีตทดสอบ (~5 นาที)

1. เปิด Google Sheet ของร้าน → เมนู **ไฟล์ → ทำสำเนา**
2. ตั้งชื่อให้รู้ว่าเป็นของทดสอบ เช่น `[ทดสอบ] Doomuenjing Inventory`
3. เปิดสำเนาที่ได้ → คัดลอก **ID จาก URL** เก็บไว้
   `docs.google.com/spreadsheets/d/`**`ตรงนี้คือ ID`**`/edit`

> 💡 ไม่ต้องลบข้อมูลออก — เป็นสำเนา แก้อะไรก็ไม่กระทบของจริง

---

## ขั้นที่ 2 — Firebase ทดสอบ (~10 นาที)

1. เปิด **console.firebase.google.com** → **Add project**
   ตั้งชื่อ เช่น `dmj-push-test` → ปิด Google Analytics ได้ (ไม่ต้องใช้)
2. ในโปรเจกต์ → ไอคอนเฟือง **Project settings** → แท็บ **General**
   → เลื่อนลงหา **Your apps** → กดไอคอน **`</>`** (Web) → ตั้งชื่อ app → Register
   → จะได้กล่องโค้ดที่มีค่า **5 ตัวนี้ ให้ก๊อปเก็บไว้**
   ```
   apiKey · projectId · messagingSenderId · appId
   ```
3. แท็บ **Cloud Messaging** → หัวข้อ **Web configuration** → **Web Push certificates**
   → กด **Generate key pair** → ก๊อป **Key pair** (คือ VAPID public key) เก็บไว้
4. แท็บ **Service accounts** → **Generate new private key** → ได้ไฟล์ `.json` มา 1 ไฟล์
   **เก็บไว้ในเครื่อง อย่าส่งให้ใครทางแชท อย่าอัปขึ้น GitHub**

> ค่า 5 ตัวในข้อ 2-3 เป็น **ตัวระบุสาธารณะ** ส่งให้ผมได้
> ไฟล์ `.json` ในข้อ 4 เป็น **ความลับ** — ใส่เองในขั้นที่ 3 เท่านั้น

---

## ขั้นที่ 3 — GAS ทดสอบ (~15 นาที)

1. เปิด **script.google.com** → **โปรเจกต์ใหม่** → ตั้งชื่อ `[ทดสอบ] DMJ Backend`
2. คัดลอกเนื้อไฟล์ `appsscript_complete.gs` จาก branch นี้ ไปวางแทนโค้ดในตัวแก้ไข
3. ⚙️ **Project Settings** → ติ๊ก **"Show appsscript.json"** → กลับไปแท็บ Editor →
   เปิดไฟล์ `appsscript.json` แล้ววางเนื้อจากไฟล์ `appsscript.json` ของ branch นี้
4. ⚙️ **Project Settings** → **Script Properties** → กด **Add script property**
   ใส่ **ครบ 4 ตัวนี้ ไม่ขาดไม่เกิน**

   | ชื่อ (ก๊อปได้เลย) | ค่า |
   |---|---|
   | `SHEET_ID` | ID ของ**ชีตทดสอบ**จากขั้นที่ 1 |
   | `APP_TOKEN` | พิมพ์อะไรก็ได้ที่เดายาก เช่น `test_` ตามด้วยตัวเลขมั่ว ๆ |
   | `FCM_SERVICE_ACCOUNT_JSON` | เปิดไฟล์ `.json` จากขั้นที่ 2.4 แล้ว **ก๊อปทั้งไฟล์** มาวาง |
   | `STAGING_NO_EXTERNAL` | พิมพ์ `true` **(ตัวเล็กทั้งหมด)** |

   > 🔒 **`STAGING_NO_EXTERNAL` = true คือสวิตช์ความปลอดภัยหลักของ staging**
   > มันตัดการติดต่อ **ZORT และ LINE (ส่งข้อความ)** ทิ้ง **ก่อน** ที่จะมีคำขอออกจากสคริปต์
   > — ไม่ใช่ปล่อยให้ยิงไปแล้วโดนปฏิเสธที่ปลายทาง
   >
   > ทำไมต้องมี: แค่ "ไม่ใส่" ค่า ZORT/LINE **ยังไม่ปลอดภัยพอ** เพราะโค้ดจะถอยไปใช้ค่า
   > `PLACEHOLDER_…` ซึ่งนับเป็น "มีค่า" → เดินต่อไปยิงจริงแล้วค่อยโดน 401
   > แปลว่า**มีคำขอวิ่งออกไปหา LINE/ZORT จริง** ซึ่ง staging ต้องไม่ทำ
   >
   > ⚠️ **ห้ามใส่ค่านี้ในโปรเจกต์ของจริงเด็ดขาด** — ใส่แล้วแจ้งเตือน LINE กับ sync ZORT
   > จะหยุดทำงานทั้งระบบ · ⚠️ **การล็อกอินด้วย LINE ยังใช้ได้ปกติ** (คนละส่วนกับการส่งข้อความ)

5. **🚫 ห้ามใส่ property พวกนี้เด็ดขาด** (ถ้าเผลอใส่ = staging อาจไปแตะระบบจริง)

   ```
   ZORT_STORE   ZORT_APIKEY   ZORT_SECRET
   LINE_ACCESS_TOKEN   LINE_ACCESS_TOKEN_2
   LINE_USER_ID        LINE_USER_ID_2
   LINE_GROUP_ID       LINE_GROUP_ID_2
   ```
   → ปล่อยว่างไว้ + มี `STAGING_NO_EXTERNAL=true` = ปลอดภัย 2 ชั้น

   **property ที่ "ใส่ก็ได้ ไม่ใส่ก็ได้" (ปล่อยว่างดีกว่าสำหรับ Phase 1)**
   `NOTI_QUEUE_ENABLED` · `INAPP_NOTI_ENABLED` · `REQUIRE_LOGIN` · `PRODUCT_OWNER_ENABLED`
   → Phase 1 ทดสอบ Push ได้โดย**ไม่ต้องเปิดตัวไหนเลย**
6. **🚫 ห้ามกดรัน** `setupNotiSystem` `setupAttendanceMaintenance` `setupShipmentArchiveTrigger`
   `setupShelfSweepTrigger` หรืออะไรก็ตามที่ขึ้นต้นว่า `setup…` **ยกเว้น `setupPush`**
   → พวกนั้นสร้าง trigger ที่จะวิ่งเองทุกวัน/ทุกนาที ซึ่งในโปรเจกต์ทดสอบไม่ต้องการ
7. กดปุ่ม **Deploy → New deployment** → เลือกชนิด **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   → กด Deploy → **ก๊อป URL ที่ลงท้ายด้วย `/exec`** เก็บไว้ (คนละตัวกับของจริงแน่นอน)
8. เลือกฟังก์ชัน **`checkPushStatus`** จาก dropdown ด้านบน → กด ▶ Run → ดูผลที่ **Execution log**
   ควรเห็น `FCM_SERVICE_ACCOUNT_JSON: ✅ ตั้งแล้ว · project_id=…`
   (ฟังก์ชันนี้อ่านอย่างเดียว ไม่เขียนอะไร ไม่มีความลับใน log)
   ในผลควรเห็น 2 บรรทัดนี้ด้วย — **ถ้าไม่ตรง อย่าไปต่อ**:
   ```
   STAGING_NO_EXTERNAL: ✅ เปิด — ตัด ZORT/LINE ก่อนยิง network
   FCM_SERVICE_ACCOUNT_JSON: ✅ ตั้งแล้ว · project_id=…
   ```

9. เลือก **`setupPush`** → ▶ Run **หนึ่งครั้ง** (เปิดสวิตช์ `PUSH_ENABLED`)
   ปิดกลับได้ทุกเมื่อด้วย **`disablePush`**

### ✅ ฟังก์ชันที่อนุญาตให้รันในโปรเจกต์ทดสอบ — มีแค่ 3 ตัว

| ฟังก์ชัน | ทำอะไร | รันซ้ำได้ไหม |
|---|---|---|
| `checkPushStatus` | อ่านสถานะอย่างเดียว ไม่เขียนอะไร ไม่ยิง network | ได้ไม่จำกัด |
| `setupPush` | เปิดสวิตช์ `PUSH_ENABLED` | ได้ |
| `disablePush` | ปิดสวิตช์ (หยุดส่งใหม่) | ได้ |

**🚫 ห้ามรันตัวอื่นทั้งหมด** โดยเฉพาะอะไรที่ขึ้นต้นว่า `setup…` หรือ `sync…` —
พวกนั้นสร้าง trigger ที่จะวิ่งเองทุกวัน/ทุกนาที หรือดึงข้อมูลจากระบบภายนอก

## ขั้นที่ 4 — เว็บทดสอบ (ผมทำให้ได้เมื่อคุณอนุญาต)

ต้องแก้ `config.js` ให้ชี้ไป **GAS ทดสอบ** (ขั้น 3.7) และใส่ค่า Firebase 5 ตัว (ขั้น 2.2-2.3)
แล้ว deploy เป็น **Cloudflare Pages preview** ของ branch นี้ ซึ่งได้ **ลิงก์คนละอันกับเว็บจริง**

> ⚠️ ตรงนี้ต้อง commit + push ขึ้น branch ก่อน Cloudflare ถึงจะสร้าง preview ให้
> **ยังไม่ทำจนกว่าคุณจะอนุญาตเป็นขั้นตอนแยก** — และ **ไม่แตะ `master`** เพราะ push เข้า
> `master` จะทริกเกอร์ทั้ง Cloudflare production และ GitHub Actions ที่ยิงโค้ดขึ้น GAS จริง

## ขั้นที่ 5 — ทดสอบบนมือถือ

1. เปิด **ลิงก์ preview** บน iPhone/iPad ด้วย Safari
   → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม** → **ปิด Safari แล้วเปิดจากไอคอน**
   (iOS ขอสิทธิ์แจ้งเตือนได้เฉพาะตอนเปิดจากไอคอนเท่านั้น · ต้อง iOS 16.4 ขึ้นไป)
2. เข้าเมนู **เชื่อมต่อ** → การ์ด **🔔 ทดสอบแจ้งเตือน**
3. กด **"เปิดแจ้งเตือนบนเครื่องนี้"** → อนุญาต
4. กด **"ส่งข้อความทดสอบ"** → ควรเห็นแจ้งเตือนเด้ง **1 อัน**
5. ลองซ้ำตอน: เปิดแอปค้างอยู่ / สลับไปแอปอื่น / **ปิดแอปสนิท** — จดผลทั้ง 3 แบบ
6. ทำซ้ำบน **Android Chrome** และ **iPad**

## เลิกใช้ / ย้อนกลับ

| อยากทำอะไร | ทำยังไง |
|---|---|
| หยุดส่งทันที | GAS ทดสอบ → รัน **`disablePush`** |
| เลิกใช้ทั้งหมด | ลบโปรเจกต์ Firebase + ลบโปรเจกต์ GAS ทดสอบ + ลบชีตสำเนา |
| กลัวคีย์รั่ว | Firebase → Service accounts → ลบคีย์เดิม สร้างใหม่ แล้วแก้ Script Property |
| อยากมั่นใจว่า staging ไม่แตะของจริง | รัน `checkPushStatus` → ต้องเห็น `STAGING_NO_EXTERNAL: ✅ เปิด` |

**ของจริงไม่ถูกแตะเลยในทุกขั้น** — คนละชีต คนละ GAS คนละลิงก์เว็บ คนละ Firebase

## สิ่งที่ยังไม่รู้จนกว่าจะทดสอบจริง

ขั้นที่ 5 คือจุดเดียวที่ตอบคำถามพวกนี้ได้ — **mock ตอบแทนไม่ได้**:

1. iPhone ที่ปิดแอปสนิทแล้ว **ข้อความถึงจริงไหม**
2. แตะแจ้งเตือนแล้วเปิดแอปตัวเดิม หรือเปิดหน้าต่างใหม่ซ้อน
3. ได้แจ้งเตือน **1 อัน** จริงไหมในทุกสถานะของแอป
4. ถ้าข้อ 1 ไม่ผ่าน = Push แทน LINE ไม่ได้ ต้องรายงานตรง ๆ ไม่กลบ
