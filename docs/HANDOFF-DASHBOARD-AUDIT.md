## ✅ สรุปสิ่งที่แก้

### Phase 0 — วินิจฉัยราคาต้นทุน (เจ้าของรัน `debugPurchasePrices()` แล้ว)

**ZORT ไม่มีราคาต้นทุนให้เลย** — ทุกฟิลด์ราคาใน line item ของ PO เป็น 0 หมด
(`pricepernumber`, `totalprice`, `*_pretax`, `*_vat`) · 91 item ใน 30 วัน มีราคาแค่ 3 (3%)
**ไม่มี fallback field ให้ใช้** · ดัชนีคอลัมน์ในชีตถูกต้อง (แถวข้อมูลตัวอย่างปี 2023 อ่านราคาได้ปกติ)

→ สาเหตุจริงคือ **คนสร้าง PO ใน ZORT ไม่ได้กรอกราคาต่อหน่วย** ไม่ใช่บั๊กในโค้ด
→ **คำนวณ COGS / gross margin / inventory turnover จริงไม่ได้** จนกว่าจะมีราคาทุนที่ต้นทาง

### Phase 1 — 5 เลขบนหน้าภาพรวม (อยู่ใน `cc00a23`)

| เดิม | ตอนนี้ |
|---|---|
| `↓99.9%` ทุกเดือน | เทียบเดือนที่กดเลือกกับเดือนก่อนหน้า**ตามปฏิทินจริง** · เดือนที่ยังไม่จบ → เทียบ "วันที่ 1–N กับเดือนก่อนช่วงเดียวกัน" + ป้าย "ผ่านไป N วัน" · วันที่ 1–2 หรือข้อมูลรายวันไม่ครอบคลุม → ไม่โชว์ delta เลย |
| `0 SKU มียอดขาย` | `nSoldPeriod` นับตามช่วงเวลาที่เลือกฝั่ง frontend (backend ไม่รู้ว่าผู้ใช้กดดูเดือนไหน) |
| KPI `1.00×` ยอดขาย/ต้นทุนสต๊อก | **ถอด KPI ออก** · KPI ของ owner เหลือ 3 ใบ → `row-3` (แก้ CSS ให้ `row-3` เรียง 2+1 บนมือถือ) |
| `มูลค่าซื้อรวม ฿1` | โชว์เฉพาะตอนราคาครบทุกรายการ (`costComplete`) · ไม่ครบ → `—` + แถบบอกให้กรอกราคาใน ZORT |
| มูลค่าสต๊อก ฿36.23M (ปลีก) | **฿28.98M** ราคาขายส่ง = ปลีก × `WHOLESALE_RATIO` + ป้าย "ราคาขายส่ง (ปลีก −20%)" |

### Phase 2 — ครบ 8/8 จุด

**กลุ่ม A** (อยู่บน master แล้ว): StockView `suggestedQty` (จุดอันตรายสุด — เดิมต่ำกว่าจริง ~33%
= เสี่ยงสั่งของขาด · `overstocked` พลอยถูกแก้ด้วยเพราะคิดต่อจาก `avgMonthly` เดียวกัน) ·
`velocity` · `momMovers` · `deadStock` (offset `[1,2]`)

**กลุ่ม B** (branch, รอ merge) — พวก "ครึ่งแรก vs ครึ่งหลัง" + regression:
StockView `declining` · CategoryView ป้าย "กำลังมาแรง" · TrendsView `enriched`+`fading` ·
SeasonView · OverviewView `forecast`

⚠️ **`forecast` เปลี่ยนความหมายการ์ดด้วย** ไม่ใช่แค่ filter — พอตัดเดือนที่ยังไม่จบออก
เป้าพยากรณ์ 1 ก้าวถัดไปมักกลายเป็น **เดือนปัจจุบัน** จึงส่ง `targetKey`/`isCurrentMonth`/
`baseMonthKey` ออกมาให้หัวการ์ดเขียนป้ายตามจริง ("ประมาณยอดขาย ส.ค. 26 (ทั้งเดือน)")
และ `revChangePct` เทียบกับเดือนเต็มล่าสุด ("vs ก.ค. 26") แทน "vs เดือนนี้"

## 📌 สิ่งที่เจ้าของต้องทำเอง (ไม่ใช่งานโค้ด)

1. **ไม่มีอะไรต้อง merge แล้ว** — งานทั้งหมดอยู่บน `master` เรียบร้อย
2. **ปรับอัตราขายส่งได้เอง** ที่ Script Property **`WHOLESALE_RATIO`**
   เช่น `0.85` = ปลีก −15% · ไม่ตั้ง = `0.8` · ค่าที่ไม่ใช่ตัวเลข/นอกช่วง `0 < r ≤ 1` → กลับไปใช้ 0.8
3. **ถ้าอยากได้ KPI ต้นทุน/กำไร/turnover จริงกลับมา** → ต้อง**กรอกราคาต่อหน่วยใน PO ฝั่ง ZORT**
   ให้ครบ · แก้ที่ต้นทางแล้วการ์ด "ของเข้าใหม่" จะโชว์ยอดเอง ไม่ต้องแก้โค้ด
   · ตรวจซ้ำได้ตลอดด้วยการรัน **`debugPurchasePrices()`** ใน GAS editor (อ่านอย่างเดียว ไม่แก้ข้อมูล)

## ⚠️ กับดักที่เจอมาแล้วในงานนี้ (อย่าพลาดซ้ำ)

1. **`completeMonths` ถูกเรียกด้วย 2 รูปแบบ** — `p.monthly` = array ของ `{month}` ·
   `monthLabels` = array ของ string · รองรับแบบเดียว = อีกแบบเงียบ ๆ ไม่กรองเลย ไม่มี error
2. **เทียบตัวเลขต้องมาจากแหล่งเดียวกันทั้งสองฝั่ง** — `monthlySeries` ตัดหมวด "ไม่มีรหัสสินค้า"
   ออก แต่ `dailySeries` ไม่ตัด · `momInfo` จึงอ่าน `dailyByCat` เองด้วยกติกาเดียวกับ `monthlySeries`
3. **ห้ามแก้ `p.price` ที่ต้นทางเพื่อทำราคาขายส่ง** — POS/ใบเสนอราคาใช้ตัวเดียวกัน จะเพี้ยนทั้งระบบ
   · คูณเฉพาะตอนคิด `stockValue*` เท่านั้น และต้องคูณครบทั้ง 3 ตัว (รวม/คลัง/หน้าร้าน)
   ไม่งั้นคลัง+หน้าร้านบวกกันไม่เท่ายอดรวม
4. **`totals` ไม่เคยถูกตัดใน `PAYLOAD_VARIANT_DROPS_`** → `wholesaleRatio` ถึงทุก role ปลอดภัย
5. **อย่าเปลี่ยน `.row-3` เป็น 1 คอลัมน์บนมือถือ** — เพิ่งแก้ให้เป็น 2+1 เพราะการ์ดยาวเป็นตับ
   (มือถือคือจอหลักของร้าน) · `TransferView` ใช้ `.row-3` ด้วย ได้ประโยชน์เหมือนกัน
