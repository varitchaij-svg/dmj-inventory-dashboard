## 🔧 เจ้าของต้องทำเองใน GAS editor (สำหรับข้อ 3 — clasp push ไม่รันให้)

รอ GitHub Actions deploy `.gs` เสร็จก่อน (ไม่กี่นาทีหลัง merge) แล้วเปิด **Apps Script editor**:

1. รัน **`previewZortDeletedProducts()`** — อ่านอย่างเดียว · ดู Log ว่าจะซ่อนตัวไหนบ้าง กี่รายการ
   - ถ้าขึ้น `❌ ดึง ZORT ไม่ครบ` → ยังไม่ต้องทำอะไร ลองใหม่ทีหลัง (เน็ต/quota)
   - ถ้าขึ้น `⚠️ เกิน 40%` → **อย่ากด hide** ให้เช็คว่า ZORT ดึงครบจริงก่อน (น่าจะผิดปกติ)
2. ถ้ารายการถูกต้อง → รัน **`hideDeletedFromZort()`** — ซ่อนจริง (soft-delete)
3. กดปุ่ม **Sync** ในแอป หรือรอ cache หมด → สินค้าที่ซ่อนจะหายจากเว็บ
4. **กู้กลับได้เสมอ**: `unhideProduct("BK001")` (ทีละตัว) หรือ `clearHiddenProducts()` (ทั้งหมด) ·
   ดูรายการที่ซ่อนอยู่: `listHiddenProducts()`

> หมายเหตุ: ฟังก์ชันพวกนี้ชื่อไม่มี `_` ต่อท้าย → โผล่ใน dropdown ของ GAS editor ให้เลือกรันได้เลย

## 📋 งานที่ค้าง — #3 MTO เป็น "กลุ่มสินค้า/bundle" (ยังไม่ทำ — ดีไซน์ล็อกแล้ว)

เจ้าของสั่งไว้ + ตอบคำถามล็อกดีไซน์แล้ว (ส.ค. 2026) — **ยังไม่เริ่มโค้ด** รอลองของข้อ 2 ก่อน

**โจทย์**: ในหมวด MTO กด BK001 → เลือกสินค้าจริงที่จะใช้เพื่อ **คิดราคา** → สรุปในใบเสนอราคาเป็น
บรรทัดเดียว "BK001 — 1,000฿" **โดยไม่แจง**ว่า 1,000฿ ใช้ของอะไรบ้าง · แต่ต้อง **เตรียมหักสต็อก
ของประกอบ** ไว้ด้วย

**การตัดสินใจที่ล็อกแล้ว** (ห้ามเดาใหม่ — เจ้าของเลือกเอง):
1. **สูตรของประกอบ = เลือกใหม่ทุกครั้งที่ทำใบ** (ad-hoc composition) — ไม่ใช่สูตรตายตัวต่อ SKU
   → composition ต้องผูกกับ **"บรรทัดในใบ"** ไม่ใช่ต่อ BK001 · เก็บ sub-items ใน state ของ cart line
2. **การหักสต็อก = แค่ "บันทึกไว้ให้คนคลังจัด/หักเอง" ไม่ auto-หักผ่าน ZORT** (เจ้าของเลือกทางเสี่ยงต่ำ)
   - ⚠️ **ห้าม** ไปแตะ `createSaleBill`/`deductFrontStoreForSale_` ให้หักของประกอบอัตโนมัติ —
     เส้นทางขาย+ZORT ไม่รู้จัก bundle → หักสองเด้ง/สต็อกเพี้ยน (ตรงกับบทเรียนที่เจ็บสุดใน CLAUDE.md)
   - สิ่งที่ทำแทน: บันทึก composition เป็น **"ใบเตรียมของ/รายการของที่ใช้"** ให้คนคลังเห็นแล้วหักเอง

**แนวทางที่แนะนำ (เฟส):**
- **เฟส 3ก (ทำก่อน)**: กด BK001 → เปิด modal เลือกสินค้าประกอบหลายตัว + จำนวน → คิดยอดรวม →
  ให้แก้ราคาสุดท้าย (bundle price) ได้ (MTO มักตั้งราคาเหมา ≠ ผลรวม) → cart line เก็บ
  `{ sku:"BK001", name, price(เหมา), components:[{sku,qty,...}] }` → พิมพ์บรรทัดเดียวในใบเสนอราคา
  (ไม่โชว์ components ในเอกสารลูกค้า)
- **เฟส 3ข**: ส่ง composition ไปกับใบเสนอราคา/ตอนอนุมัติ → สร้าง "ใบเตรียมของ" ให้คนคลัง
  (แสดง components + จำนวน) · **ยังไม่หักสต็อกอัตโนมัติ**
- **เฟส 3ค (ทีหลังสุด ถ้าเจ้าของอยาก)**: auto-deduct — **งานเสี่ยงสูง** ต้องทำแบบ `cid`/`tid`
  (idempotent) และแก้ semantics การหักสต็อกฝั่ง ZORT ให้ชัดก่อน · อย่าบันเดิลกับ 3ก/3ข

**จุดต้องระวัง (จากการสำรวจโค้ดรอบนี้):**
- **ใบเสนอราคาไม่หักสต็อกอยู่แล้ว** (หักจริงตอนขาย `createSaleBill` เท่านั้น) → เฟส 3ก/3ข
  ไม่แตะสต็อกเลย ปลอดภัย
- `computeBillTotals` คิดส่วนลดขายส่ง/VAT จาก line item — bundle เป็น 1 line ราคาเหมา
  ต้องดูว่าจะให้เข้ากฎส่วนลดไหม (น่าจะ**ไม่** — ราคาเหมาคือราคาสุทธิแล้ว คล้าย `pricesFinal`)
- ต้องกันไม่ให้ bundle line ไปโดน `quoteHydrateItems_` / edit-mode price logic ทับ (composition
  ต้อง persist ในร่าง/ใบเดิมด้วย — ปัจจุบันร่างไม่เก็บ components)
- BK001 อาจ**ไม่มีใน ZORT** (เป็นสินค้าเสมือน) → ตอน `createQuotation` ส่งให้ ZORT ต้องดูว่า
  ZORT รับ SKU ที่ไม่มีจริงไหม (อาจต้องส่งเป็น line ที่ไม่มี SKU / custom name)
