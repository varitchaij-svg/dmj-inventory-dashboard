## งานที่เหลือ (ตามแผน `zesty-herding-puddle.md`)

### ส่วนที่ 1 — ล็อกอิน (สำคัญสุด: บล็อกพนักงานทั้งร้านได้ถ้าพัง)

1. **`postAuthAction` → `dmjFetch` + `dmjJson`** (`app.jsx:910-920`) — ตอนนี้ยังใช้ `fetch`/
   `res.json()` ดิบ ทั้งที่ `CLAUDE.md` เคยเขียนว่าเปลี่ยนหมดแล้ว (ไม่จริง) ครอบ 4 action:
   authLine(25s)/me(20s)/logout(20s)/claimLoginHandoff(8s — ยิงทุก 4 วิ ตั้งยาวกว่ารอบ poll
   จะซ้อนกัน) + จุดอื่นที่ยังเป็น fetch ดิบ: `app.jsx:1415`, `:1518`, `:419` (`handlePin`)
2. **จอ `checking` ต้องมีทางออกเสมอ** (`app.jsx:1613-1619`) — ตอนนี้เป็นสปินเนอร์เปล่า
   ไม่มี timeout ไม่มีปุ่ม → เพิ่มนับวินาที + ข้อความเตือนที่ 12s + ปุ่ม "กลับไปหน้าล็อกอิน" ที่ 30s
3. **poll handoff กันยิงซ้อน + ถอยห่าง** (`app.jsx:1487-1505`) — ตอนนี้ทุก 4 วิคงที่ ไม่มี
   in-flight guard → เพิ่ม guard + backoff (4s×3 → 8s → 15s) + ยืด TTL 15→30 นาที (ต้องแก้
   พร้อมกันทั้ง 3 จุด: `app.jsx:769`, `:774`, `appsscript_complete.gs:514`)
4. **handoff ต้องไม่ถูกกินทิ้งถาวร** (`appsscript_complete.gs:541-569`) — `cache.remove`
   เกิดก่อนส่งคำตอบ ถ้าคำตอบค้าง token หายถาวร → เปลี่ยนเป็นเขียนทับด้วย TTL สั้น (60s) แทน
5. **`resolveSession_` เลิกอ่าน+เขียนชีตทุก request** (`appsscript_complete.gs:374-393`) —
   cache ผลลัพธ์ 300s ต่อ token (แฮชคีย์) + เขียน `lastSeenAt` เฉพาะเมื่อเก่ากว่า 10 นาที +
   **ต้องล้าง cache ตอน revoke/เปลี่ยน role** ไม่งั้น logout แล้วยังใช้ได้ต่อ

### ส่วนที่ 2 — แถบความคืบหน้า (ผู้ใช้ขอเอง)

- จอโหลดข้อมูลหลัก: นับไบต์จริงจาก `res.body.getReader()` เทียบกับขนาดครั้งก่อน
  (`localStorage.dmj_last_payload_bytes`) — ห้ามทำลาย error path เดิมของ `dmjJson`
- จอล็อกอิน: ก้อนเล็กเกินกว่าจะมี % ที่มีความหมาย → โชว์วินาทีที่ผ่านไปแทน

### ส่วนที่ 3 — Phase 8 ขั้นวัด (ก่อนตัดคอลัมน์จริง)

- เพิ่ม log ใน `logPayloadSizes_` (`appsscript_complete.gs:10123-10142`): ไบต์ชื่อคีย์ vs
  ค่าใน `products[]`, จำนวนแถวต่อคีย์, ตัวอย่าง `imageUrl` หา prefix ร่วม
- กรอกผลลง `docs/PLAN-PHASE8-PAYLOAD.md` แล้วค่อยตัดสินใจตัดคอลัมน์จริง (`pv=3`)
