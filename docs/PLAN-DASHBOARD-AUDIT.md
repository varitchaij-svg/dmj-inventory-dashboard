## 1. บั๊กที่เห็นด้วยตาในภาพ (P0 — แก้ก่อน)

### 1.1 `↓ 99.9%` — เทียบผิดเดือน + เทียบกับเดือนที่ยังไม่จบ

`views-main.jsx:1150-1152`

```js
const prevRev = monthlySeries[monthlySeries.length-2].rev;   // ← เดือนรองสุดท้ายในข้อมูล
const curRev  = monthlySeries[monthlySeries.length-1]?.rev;  // ← เดือนสุดท้ายในข้อมูล
const momDelta = prevRev > 0 ? ((curRev - prevRev) / prevRev * 100).toFixed(1) : null;
```

แล้วถูกใช้ที่ `views-main.jsx:1677-1681` → `deltaVal` → แสดงคู่กับป้าย `subLabel` ที่เป็น
**เดือนที่ผู้ใช้เลือก** (`views-main.jsx:1867-1869`)

ปัญหา 2 ชั้นซ้อนกัน:
1. `momDelta` ไม่สนใจ `activeMonth` เลย — กด มิ.ย. หรือ ก.ค. ก็ได้เลขเดียวกัน
2. เดือนสุดท้ายในข้อมูลคือ **08/2026** ซึ่งวันนี้เพิ่งเข้าวันที่ 1 → `curRev ≈ 0`
   → `(0 − 1,280,000) / 1,280,000 = −99.9%` ตรงกับที่เห็นเป๊ะ

`aggregateAndWriteSales_` (`appsscript_complete.gs:4813-4825`) สร้างคอลัมน์เดือนใหม่ทันที
ที่มีบิลใบแรกของเดือน → เดือนที่ยังไม่จบจะโผล่ใน `monthLabels` เสมอ

**แก้**: คำนวณ delta จาก `activeMonth` เทียบเดือนก่อนหน้า `activeMonth` จริง ๆ ·
ถ้า `activeMonth` = เดือนปัจจุบัน ให้เทียบแบบ **pro-rate** (วันที่ผ่านไป/วันทั้งเดือน)
หรือซ่อน badge แล้วขึ้นป้าย "เดือนนี้ยังไม่จบ (ผ่านไป N/31 วัน)" แทนการโชว์ −99.9%

`appsscript_complete.gs:2372-2384` — `totals` **ไม่มีคีย์ `nSold`** (มีแต่ `totalSoldQty`/`totalSoldRev`)

`views-main.jsx:1310-1313` อ่าน `totals.nSold` → `undefined` → `fmtN(undefined)` = `"0"`
(`ui.jsx:5`)

สังเกตได้ว่าเป็นบั๊กจริง เพราะพอ**เลือกหมวด** โค้ดจะไปเข้า branch ที่คำนวณเองที่
`views-main.jsx:1314-1324` แล้วเลขขึ้นถูก — ผิดเฉพาะตอน "ทุกหมวด"

**แก้**: เพิ่ม `nSold` ใน `totals` ฝั่ง GAS · และเปลี่ยนความหมายให้เป็น
"SKU ที่มียอดขาย **ในช่วงเวลาที่เลือก**" ไม่ใช่ตลอดกาล (ไม่งั้นจะขัดกับ KPI ข้าง ๆ ที่เป็นรายเดือน)

### 1.3 `ยอดขาย / ต้นทุนสต๊อก 1.00×`

`views-main.jsx:1888-1891`

```js
value={stockAgg.val > 0 ? `${(stockAgg.soldRev / stockAgg.val).toFixed(2)}×` : "—"}
```

- ตัวตั้ง `totals.totalSoldRev` = ยอดขาย **สะสมตั้งแต่ ม.ค. 2024** (~2.5 ปี)
- ตัวหาร `totals.totalStockValue` = มูลค่าสต๊อก **ณ วันนี้** และเป็น **ราคาขายปลีก** ไม่ใช่ต้นทุน
- ที่ได้พอดี 1.00× เพราะบังเอิญ (1.2M/เดือน × ~30 เดือน ≈ 36M ≈ มูลค่าสต๊อก) **ไม่ได้ hard-code**

ป้ายเขียนว่า "หมุนเวียนสินค้า" แต่สูตรไม่ใช่ inventory turnover

**แก้**: `turnover = COGS 12 เดือนล่าสุด ÷ มูลค่าสต๊อกที่ราคาทุน` (ต่อปี) ·
ต้องรอข้อ 1.4 (ราคาต้นทุนจริงจาก PO) ก่อน ไม่งั้นก็ยังเป็นตัวเลขปลอมอยู่ดี

### 1.4 `มูลค่าซื้อรวม ฿1`

`views-main.jsx:1344` → `g.cost += (pu.qty||0) * (pu.unitPrice||0)`
`appsscript_complete.gs:7712` → `unitPrice: parseNum_(r[27])`
`appsscript_complete.gs:6650-6653` → `syncZortPurchases` เขียน `row[27] = Number(item.pricepernumber || 0)`

จำนวนชิ้น (คอลัมน์ 26) ออกมาถูก 11,848 · ชื่อ/SKU (คอลัมน์ 24-25) ถูก → **ดัชนีคอลัมน์ไม่เพี้ยน**
เหลือความเป็นไปได้ว่า `pricepernumber` ที่ ZORT คืนมาสำหรับ PO ชุดนี้เป็น 0/ว่าง

⚠️ **ข้อนี้ยังฟันธงสาเหตุไม่ได้จากโค้ดอย่างเดียว — ต้องดูข้อมูลจริงก่อน** (ดู Phase 0)

**แก้ที่ทำได้แน่นอนโดยไม่ต้องรอ**: ห้ามโชว์ยอดรวมเงียบ ๆ เมื่อข้อมูลไม่ครบ →
นับว่ามีกี่ SKU ที่ไม่มีราคา แล้วโชว์ `฿xxx (ไม่มีราคา 36/38 รายการ)` ·
เพิ่ม fallback `totalprice ÷ number` ถ้า `pricepernumber` ว่าง

หน้าที่พังตามกันไปด้วย: **MarginView** ใช้แหล่งราคาเดียวกัน (`views-analytics.jsx:7969-7981`)
→ ถ้า PO ไม่มีราคา ค่า coverage จะต่ำ กำไรที่โชว์ครอบคลุมสินค้าน้อยมาก

### 1.5 มูลค่าสต๊อกต้องคิดที่ราคาขายส่ง (−20%) ← ตามที่เจ้าของสั่ง

`appsscript_complete.gs:2284-2286`

```js

p.stockValueWH    = (p.qtyWH    || 0) * p.price;
```

`p.price` มาจาก `applyQtyLocToProduct_` (`appsscript_complete.gs:7862`) = ราคาขายปลีกที่ ZORT sync มา

น่าสนใจ: ระบบ**มี** `COST_RATIO = 0.8` อยู่แล้ว (`appsscript_complete.gs:207`) และใช้กับ
`p.cost` / `p.profit` — แต่ **ไม่เคยถูกใช้กับ `stockValue`** เลย

**ตัวเลขหลังแก้**

| | ตอนนี้ (ปลีก) | หลังแก้ (ขายส่ง −20%) |
|---|---|---|

⚠️ **จุดที่ต้องคุยให้ชัดก่อนแก้**: "ราคาขายส่ง" ≠ "ราคาทุน"

## 3. ความไม่สอดคล้อง — เลขเดียวกันคนละหน้าไม่ตรงกัน (P1)

1. **MTO / "ไม่มีรหัสสินค้า" ถูกนับบ้างไม่นับบ้าง**
   `views-main.jsx:1310-1325` — "ทุกหมวด" ใช้ `totals.*` ที่รวม MTO + ไม่มีรหัส
   แต่พอเลือกหมวดกลับตัด MTO ออก → บวกทุกหมวดแล้วไม่เท่ากับ "ทุกหมวด"
   `sellable` (`:1308`) ก็ไม่ตัด "ไม่มีรหัสสินค้า" ทั้งที่ `topSellers`/`topByCategory` ตัด

2. **MarginView คิดกำไรจากราคาป้าย ไม่ใช่ราคาที่ขายได้จริง** ← เกี่ยวกับ −20% โดยตรง
   `views-analytics.jsx:7997-8008`
   ```js
   unitMargin = price - cost;          // price = ราคาปลีกจาก ZORT
   profit     = unitMargin * soldQty;
   ```
   ถ้าขายส่ง −20% กำไรที่โชว์ **เกินจริงเต็ม ๆ 20% ของราคาขาย**
   → ต้องเป็น `profit = soldRev − cost × soldQty` (`soldRev` คือเงินที่เข้าจริง)

3. **`soldQty` บวก `soldQtyUnscanned` แต่ `soldRev` ไม่บวก** (`appsscript_complete.gs:2277-2281`)
   → ของที่ถูกดึงไปทำงาน MTO ทำให้ "กำไร/ชิ้น × จำนวน" ใน MarginView เพี้ยน

4. **ยอดขายรวมสองหน้าไม่มีทางตรงกัน**
   Overview รวมจาก `list[].totalprice` (รายบรรทัดสินค้า) ·
   CustomerView รวมจาก `order.amount` (ยอดบิล รวมค่าส่ง/ส่วนลด)
   → ต้องมีหมายเหตุบอกผู้ใช้ ไม่งั้นจะคิดว่าระบบพัง

5. **`abcClassify` ใช้ยอดขายทั้งประวัติ** (`views-analytics.jsx:1063-1078`)
   ของที่ขายดีเมื่อ 2 ปีก่อนยังเป็นคลาส A → คิว "ควรนับก่อน"/"ควรเช็คก่อน" จัดลำดับผิด
   → ควรใช้หน้าต่าง 12 เดือนล่าสุด

6. **"ของเข้าใหม่ 30 วัน" ไม่ขยับตามเดือนที่เลือก** (`views-main.jsx:1331-1361`)
   ตั้งใจให้เป็น 30 วันล่าสุดเสมอ แต่ไปวางอยู่ใต้ตัวกรองเดือน → คนอ่านสับสน
   (สังเกตในภาพ: กด มิ.ย. กับ ก.ค. บล็อกนี้เหมือนกันเป๊ะ)

## 4. ส่วนที่ตรวจแล้วถูกต้อง ✅

- `sumRev` / `sumQty` กรองตามเดือนที่เลือกจริง (`views-main.jsx:1140-1149`)
- คลัง + หน้าร้าน = ยอดรวม (บวกถูก แค่ฐานราคาผิด)
- `buildYoYSeries` เทียบปีต่อปี ตรรกะถูก (`views-main.jsx:954-`)
- `quarterDelta` เทียบไตรมาสก่อนหน้า ข้ามปีถูก (`views-main.jsx:1664-1675`)
- `abcClassify` แบ่ง A/B/C ด้วย cumulative **ก่อนบวกตัวเอง** ถูกต้องตามหลัก Pareto
- `SeasonView` หาเดือนถัดไป `(getMonth()+1)%12+1` ถูก รวมกรณี ธ.ค.→ม.ค.
- `parseCheckDateMs` จัดการปี พ.ศ. ถูก
- `expandMonthlyCompact` กางข้อมูลย่อกลับเป็นเต็มถูกต้อง (มี test คุมอยู่)

## 7. ข้อตัดสินใจของเจ้าของ (เคาะแล้ว 1 ส.ค. 2026) ✅

1. **มูลค่าสต๊อกคงเหลือ → โชว์ราคาขายส่งอย่างเดียว**
   ตัวเลขเดียว ฿28.98M (คลัง ฿16.10M / หน้าร้าน ฿12.89M)
   · ใต้ตัวเลขมีหมายเหตุเล็ก ๆ ว่า **"ราคาขายส่ง (ปลีก −20%)"** ให้รู้ฐานที่ใช้
   · **ไม่ต้องโชว์ราคาปลีกคู่กัน ไม่ต้องมีปุ่มสลับ** — การ์ดต้องอ่านจบในแวบเดียว
   · จุดอื่นที่คูณ `price` ดิบ ๆ แล้วเรียกว่า "มูลค่า" ต้องเปลี่ยนมาใช้ฐานเดียวกันหมด:
     `views-main.jsx:1436` (deadStock), `:4882` (slowMovers), `:5360`, `:5366` (TrendsView)

2. **ตัวเลข 20% → เก็บเป็น Script Property `WHOLESALE_RATIO` (default `0.8`)**
   · ส่งค่าลงมากับ payload (เช่นใน `_debug` หรือ `totals`) ให้ frontend ใช้ค่าเดียวกัน
     ห้าม hard-code 0.8 ซ้ำฝั่งเว็บ — ไม่งั้นวันที่เปลี่ยนส่วนลด สองฝั่งจะไม่ตรงกันเงียบ ๆ
   · **ห้ามไปแก้ `COST_RATIO` เดิมให้เป็นตัวเดียวกัน** — คนละความหมาย
     (`COST_RATIO` ใช้กับ `p.cost`/`p.profit`, ตัวใหม่ใช้กับมูลค่าสต๊อก)
   · sanitize ค่าที่อ่านมา: ต้องเป็นตัวเลข 0 < x ≤ 1 ไม่งั้น fallback 0.8

3. **KPI "หมุนเวียนสินค้า" → ถ้า Phase 0 พบว่า ZORT ไม่ให้ราคาทุน PO ให้ซ่อน KPI ไปเลย**
   · ไม่ประมาณจากราคาขายส่ง — โชว์เลขที่คำนวณจากค่าสมมติแล้วเจ้าของเอาไปตัดสินใจ
     อันตรายกว่าไม่โชว์
   · ซ่อนแล้วช่อง KPI เหลือ 3 ใบ ต้องเช็คว่า grid ไม่เพี้ยน (`row-4` → `row-3`)
   · ถ้า Phase 0 พบว่า**มี**ราคาทุน → ทำ KPI ตามสูตร `COGS 12 เดือนล่าสุด ÷ มูลค่าสต๊อกที่ราคาทุน`
     และเปลี่ยนป้ายเป็น "หมุนเวียนสินค้า (ครั้ง/ปี)" ให้ตรงกับหน่วยจริง

## 8. Phase 0 — สถานะ: เขียนโค้ดเสร็จแล้ว ✅ รอเจ้าของรัน

เพิ่ม **`debugPurchasePrices()`** ใน `appsscript_complete.gs`
(section 4b ถัดจาก `exploreZortPurchases`) · **อ่านอย่างเดียว ไม่แก้ชีต ไม่เขียนอะไรกลับ ZORT**
· ไม่ log header ที่มี `apikey`/`apisecret` · ชื่อไม่มี `_` ต่อท้าย จะได้โผล่ใน dropdown (บทเรียนข้อ 1)

**ตอบ 4 คำถาม:**

| # | คำถาม | วิธีตอบใน log |
|---|---|---|
| 1 | ชีตมีราคาจริงกี่ % ในช่วง 30 วัน | นับ `แถวที่มีราคา > 0 : n / N` + ผลรวม qty/มูลค่า เทียบกับที่การ์ดโชว์ (11,848 / ฿1) ตรง ๆ |
| 2 | คอลัมน์เลื่อนหรือเปล่า | dump header 2 แถวแรก + ค่าดิบ**ทั้งแถว**ของ 2 แถวสุดท้ายพร้อม index → เห็นทันทีถ้าราคาไปอยู่คอลัมน์อื่น |
| 3 | แถวพวกนี้ใครเขียน | นับแยกตามคอลัมน์ 1: `"สั่งซื้อ"` = `syncZortPurchases` · `"ซื้อเข้า"` = สร้างในแอป |
| 4 | ZORT ให้ราคามาไหม ฟิลด์ชื่ออะไร | ยิง `GetPurchaseOrders` 30 วัน → dump JSON เต็มของ item ตัวแรก + นับทั้งชุดว่า `pricepernumber > 0` กี่ตัว เทียบกับ `totalprice > 0` |

ปิดท้ายด้วยบล็อก "สรุป" ที่ฟันธงให้เลยว่าต้นเหตุอยู่ฝั่งชีตหรือฝั่ง ZORT

**ทางแยกหลังได้ log** (เตรียมไว้ล่วงหน้า จะได้ไม่ต้องคิดใหม่):

| ผลที่ได้ | ทำต่อ |
|---|---|
| `pricepernumber` มีค่าปกติ | ต้นเหตุอยู่ฝั่งอ่าน/คำนวณ → ไล่ต่อที่ `readPurchases_` / การ์ด "ของเข้าใหม่" |
| `pricepernumber` ว่าง แต่ `totalprice` มี | แก้ `syncZortPurchases` ให้ fallback `totalprice ÷ number` แล้ว re-sync · **KPI หมุนเวียนสินค้าไปต่อได้** |
| ไม่มีราคาทั้ง 2 ฟิลด์ | **ซ่อน KPI หมุนเวียนสินค้า** ตามข้อ 7.3 · การ์ด "ของเข้าใหม่" ตัดบรรทัดมูลค่าออก เหลือ SKU/จำนวนชิ้น · MarginView โชว์ coverage ตามจริง |
| PO ไม่มี line item เลย | `syncZortPurchases` เขียนแถวว่างอยู่ → ต้องดูว่า ZORT ใช้ `PurchaseReceive` แทนหรือเปล่า |
