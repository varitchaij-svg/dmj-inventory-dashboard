## 0. ตอบคำถามสั้น ๆ ก่อน: ทำในระบบเราได้ไหม

**ได้ครับ — และเข้าทางระบบที่เรามีอยู่แล้วมาก** เพราะ 3 อย่างนี้เรามีหมดแล้ว:
LINE OA + ระบบคิวแจ้งเตือน (Sprint 3) · Google Sheets เป็นฐานข้อมูล · เว็บที่เปิดบนมือถือทุกวันอยู่แล้ว
สิ่งที่ต้องเพิ่มคือ **LIFF** (หน้าเว็บที่เปิดจากเมนู LINE), การอ่าน GPS, การถ่ายรูป, และตารางกะ

สิ่งที่ตัวอย่างที่เห็นมาทำ แล้ว **เราทำตามได้จริงทั้งหมด**:
ลงเวลาผ่าน LINE ไม่ต้องโหลดแอป · GPS กันลงเวลานอกพื้นที่ · บังคับถ่ายรูป · กะ/วันหยุด/วันลา ·
สรุปเพื่อคิดเงินเดือน · สิทธิ์แยกเจ้าของ/พนักงาน

สิ่งที่ **ควรรู้ก่อนตัดสินใจทำเอง** (พูดตรง ๆ):
- งานนี้ไม่เล็ก — ประเมิน **~5 เฟส** กว่าจะครบถึงขั้นออกรายงานเงินเดือนได้
- ของสำเร็จรูปแบบที่เห็นมีขายเดือนละหลักร้อย–พันบาท ถ้าต้องการครบ ๆ เร็ว ๆ ซื้อคุ้มกว่าเขียนเอง
- **ข้อได้เปรียบเดียวที่ของเราชนะคือ "รวมร่าง"** — พนักงานเปิด LINE ตัวเดียว เห็นทั้งงานสต็อกและลงเวลา,
  เจ้าของเห็น "ใครเข้ากะอยู่" คู่กับ "ใครนับล็อคไหน" ในระบบเดียว, และ Audit Log ผูกกับคนเดียวกัน
  ถ้าไม่ได้อยากได้ข้อนี้ ซื้อของสำเร็จรูปแล้วให้มันอยู่แยกก็จบ

**ข้อเสนอ**: เริ่มจาก **เฟส A (ลงเวลาเข้า–ออก + GPS + รูป)** ซึ่งได้ประโยชน์ 80% ด้วยงาน 20%
แล้วค่อยดูว่าจะไปต่อถึงเงินเดือนเองหรือส่งออกไปให้บัญชีทำ

## 1. ผู้ใช้เปิดยังไง (จุดตายของงานนี้)

พนักงานใช้ **มือถือส่วนตัว** (ยืนยันแล้ว) → ใช้ **LIFF** ดีที่สุด:

```
LINE OA ของร้าน → Rich Menu ปุ่มใหญ่ "⏱ ลงเวลา"
      → เปิด LIFF (คือหน้าเว็บของเราเอง /attendance) ในเบราว์เซอร์ใน LINE
      → liff.getProfile() ได้ userId ทันที ไม่ต้องล็อกอินซ้ำ ไม่ต้อง redirect
      → กดปุ่มเดียว = ลงเวลาเสร็จ
```

- **LIFF ใช้ LINE Login channel ตัวเดียวกับแผนล็อกอิน** → ตั้งค่าครั้งเดียวได้ 2 งาน
- Rich Menu = ปุ่มใหญ่ค้างอยู่ใต้ช่องแชท พนักงานที่ไม่ถนัดเทคโนโลยีหาเจอแน่นอน
  (ดีกว่าให้จำ URL หรือหา icon PWA บนหน้าจอ)
- หน้าเดียวกันนี้เปิดจาก PWA ปกติก็ได้ (ตรวจว่า `liff.isInClient()` ไหม ถ้าไม่ใช่ก็ใช้ session ปกติ)

**หน้าจอลงเวลา** (ตามภาพตัวอย่างที่ให้มา — โครงนี้ใช้ได้เลย):
- ชื่อ+รูปพนักงาน, วันที่, เวลาปัจจุบัน (นาฬิกาเดินจริง)
- ปุ่มใหญ่ 4 ปุ่ม: **เข้างาน · เริ่มพัก · กลับจากพัก · ออกงาน**
  → ปุ่มที่กดได้ตอนนี้เท่านั้นที่เป็นสีเข้ม ที่เหลือจาง (กันกดผิดลำดับ)
- แถบสถานะ 2 แถว: **GPS** (อยู่ในพื้นที่ / ห่าง 240 ม.) และ **รูปถ่าย** (บันทึกครบ / ยังไม่ถ่าย)
- ไทม์ไลน์ของวันนี้ด้านล่าง: 08:54 เข้างาน · 12:04 เริ่มพัก · …

## 2. โครงข้อมูล (Google Sheets)

### 2.1 `ลงเวลา` — event log (1 แถว = 1 การกด)
| คอลัมน์ | หมายเหตุ |
|---|---|
| A `id` | `AT-yyyyMMdd-####` |
| B `staffId` / C `ชื่อ` | จากชีต `พนักงาน` |
| D `วันที่` | `yyyy-MM-dd` (**เขียนเป็น text format** กัน Sheets แปลง — บทเรียนข้อ 2) |
| E `เวลา` | `HH:mm:ss` |
| F `serverTs` | epoch ms จาก **เวลาเซิร์ฟเวอร์** = ตัวจริงที่ใช้คำนวณ |
| G `clientTs` | เวลาจากมือถือ (ไว้จับว่าเครื่องปรับเวลาเองรึเปล่า) |
| H `ประเภท` | `in` / `breakStart` / `breakEnd` / `out` |
| I `lat` J `lng` K `accuracy` | พิกัด + ความแม่น (เมตร) |
| L `ระยะห่าง(ม.)` M `ในพื้นที่` | คำนวณจากพิกัดร้าน |
| N `รูป` | ลิงก์ไฟล์ใน Google Drive |
| O `ที่มา` | `liff` / `web` / `แก้โดยเจ้าของ` |
| P `หมายเหตุ` Q `แก้โดย` | เหตุผลตอนลืมลงเวลา / เจ้าของแก้ย้อนหลัง |

> ออกแบบเป็น **event log ไม่ใช่ 1 แถวต่อวัน** → พักหลายรอบได้ ลืมกดแล้วเติมทีหลังได้ ไม่ต้องแก้โครง

### 2.2 `กะ` — นิยามกะ
`shiftId` · `ชื่อกะ` (กะเช้า/กะบ่าย) · `เริ่ม` 09:00 · `เลิก` 18:00 · `พัก(นาที)` 60 ·
`สายได้กี่นาที(grace)` 10 · `วันที่ใช้` (จ-ส)

### 2.3 `ตารางเวร` — ใครเข้ากะไหนวันไหน
`วันที่` · `staffId` · `shiftId` · `หมายเหตุ`
→ ถ้าไม่มีแถว = ใช้กะ default ของพนักงานคนนั้น (เพิ่มคอลัมน์ `กะประจำ` ในชีต `พนักงาน`)

### 2.4 `วันลา`
`staffId` · `ประเภท` (ลาป่วย/ลากิจ/พักร้อน) · `ตั้งแต่`–`ถึง` · `เหตุผล` ·
`สถานะ` (รออนุมัติ/อนุมัติ/ไม่อนุมัติ) · `ผู้อนุมัติ` · `เวลาอนุมัติ`
+ ชีต `วันหยุดร้าน` (วันที่ · ชื่อวันหยุด) และโควตาลาต่อปีในชีต `พนักงาน`

### 2.5 `ตั้งค่าลงเวลา` (หรือ Script Properties)
พิกัดร้าน `lat,lng` · รัศมีที่ยอมรับ (เมตร, default 150) · บังคับรูปไหม ·
บังคับ GPS ไหม (`บล็อก` / `เตือนแต่ให้ผ่าน`) · เก็บรูปกี่วันแล้วลบ (default 90)

## 3. ฝั่ง GAS (endpoint ใหม่)

| action | ใคร | ทำอะไร |
|---|---|---|
| `punch` | พนักงานที่ล็อกอิน | รับ `{type, lat, lng, accuracy, photoBase64, clientTs, note}` → **ตรวจลำดับ** (กด `out` ทั้งที่ยังไม่ `in` = ปฏิเสธ) → คำนวณระยะห่าง → เซฟรูปลง Drive → เขียนแถว → คืนสถานะวันนี้ |
| `myToday` | พนักงาน | สถานะ+ไทม์ไลน์ของตัวเองวันนี้ (ใช้เปิดหน้าจอ) |
| `attendanceSummary` | owner | สรุปช่วงวันที่ × พนักงาน (ทำงานกี่ชม. สายกี่นาที ขาด ลา OT) |
| `fixAttendance` | owner | แก้/เพิ่มแถวย้อนหลัง (**ต้องบันทึก `แก้โดย` + เหตุผทุกครั้ง** ลง Audit Log ด้วย) |
| `saveShift` / `saveSchedule` | owner | จัดกะ/ตารางเวร |
| `requestLeave` | พนักงาน | ขอลา → แจ้งเตือนเจ้าของ |
| `approveLeave` | owner | อนุมัติ/ไม่อนุมัติ |

**คำนวณระยะห่าง** = Haversine (โค้ดสั้น ๆ 6 บรรทัด ไม่ต้องใช้ API ข้างนอก)

**รูปถ่าย**: ฝั่งเว็บใช้ `<input type="file" accept="image/*" capture="user">` → ย่อด้วย canvas
เหลือกว้าง ~640px คุณภาพ 0.7 (ได้ ~60–100KB) → ส่ง base64 → GAS
`Utilities.newBlob(Utilities.base64Decode(...))` → `DriveApp` โฟลเดอร์ `ลงเวลา/yyyy-MM` →
เก็บ `getUrl()` · **ห้ามส่งรูปเต็มความละเอียด** payload จะอืดและเสี่ยง timeout

## 4. การคำนวณ (ทำที่ GAS ตอนสรุป ไม่ใช่ตอนกด)

ต่อพนักงานต่อวัน:
- `เวลาเข้า` = `in` แรกของวัน · `เวลาออก` = `out` สุดท้าย
- `นาทีพัก` = ผลรวม (breakEnd − breakStart) · ถ้าลืมกด `breakEnd` → ใช้ `พัก(นาที)` ของกะแทน + ตั้งธง
- `ชั่วโมงทำงาน` = (ออก − เข้า) − นาทีพัก
- `สาย` = เข้า − (เวลาเริ่มกะ + grace) ถ้าเป็นบวก
- `OT` = ออก − เลิกกะ (ตัดเศษเป็นครึ่งชั่วโมง หรือแล้วแต่เจ้าของกำหนด)
- ธงที่ต้องมี: `ไม่ได้กดออก` · `นอกพื้นที่` · `ไม่มีรูป` · `แก้ย้อนหลัง` · `ขาดงาน` (มีเวรแต่ไม่มี `in` และไม่มีใบลา)

**กับดักเวลา (ต้องระวังมาก)**: ใช้ `Utilities.formatDate(d, "Asia/Bangkok", ...)` เสมอ ·
เก็บเป็น epoch ms · **ห้าม `new Date(string ที่มาจาก toLocaleString("th-TH"))`** — จะได้ปี พ.ศ.
แล้วเพี้ยนไป 543 ปี (บทเรียนข้อ 11 ใน CLAUDE.md เจอมาแล้ว)

## 7. ข้อจำกัดที่ต้องยอมรับ (พูดตรง ๆ ก่อนทำ)

1. **GPS ปลอมได้** — แอป mock location มีเยอะ · **รูปก็ถ่ายรูปจากจอได้** · ระบบนี้กัน
   "ลงเวลาแทนกันแบบง่าย ๆ จากบ้าน" ได้ แต่**ไม่ได้กันคนตั้งใจโกงจริงจัง** อย่าขายความคาดหวังเกินจริง
   → สิ่งที่ช่วยได้จริงคือ **เก็บหลักฐานไว้** (พิกัด+ความแม่น+รูป+เวลาเซิร์ฟเวอร์) แล้วมีหน้าจอ
   ให้เจ้าของ "เห็นความผิดปกติ" (พิกัดซ้ำเป๊ะทุกวัน, accuracy สูงผิดปกติ, ระยะกระโดด)
2. **GPS ในอาคาร/หลังคาเหล็ก แม่นแค่ 50–200 ม.** → รัศมี 150 ม. ยังตัดคนที่มาจริงทิ้งได้
   → **เฟสแรกให้ตั้งเป็น "เตือนแต่ให้ผ่าน" ก่อน** เก็บสถิติระยะห่างจริง 2 สัปดาห์ แล้วค่อยตั้งรัศมีจริง
3. **เน็ตหลุด** → เก็บการกดไว้ใน `localStorage` แล้วยิงซ้ำเมื่อออนไลน์ · ระบุชัดว่าเป็นเวลาที่กด
   (clientTs) แล้วมาร์คว่า "บันทึกย้อนหลัง"
4. **iOS ต้องกดอนุญาตตำแหน่ง/กล้อง** ครั้งแรก และถ้ากด "ไม่อนุญาต" ไปแล้วต้องไปเปิดใน Settings
   → ต้องมีหน้าจอสอนเป็นรูปภาษาไทย ไม่ใช่แค่ error message
5. **PDPA** — พิกัดกับรูปของพนักงานเป็นข้อมูลส่วนบุคคล ต้องมีข้อความแจ้ง+ให้พนักงานยอมรับ
   ตอนล็อกอินครั้งแรก, ให้เห็นเฉพาะเจ้าของ, และตั้งลบรูปอัตโนมัติ (default 90 วัน)
6. **กฎหมายแรงงาน** — บันทึกเวลาทำงานต้องเก็บไว้ตามที่กฎหมายกำหนด และการหักเงินจากการมาสาย
   มีข้อจำกัด **ให้เจ้าของเช็คกับบัญชี/ที่ปรึกษาแรงงานก่อนเอาตัวเลขไปหักเงินจริง** —
   ระบบนี้ทำหน้าที่ "บันทึกและสรุป" ไม่ใช่ตัดสินว่าหักได้เท่าไหร่
7. **เรื่องคน** — ลงเวลา+GPS+รูป เป็นเรื่องอ่อนไหวกับทีมมากกว่าฟีเจอร์สต็อกทั้งหมดรวมกัน
   ควรประกาศล่วงหน้า อธิบายว่าใช้ทำอะไร (คิดเงินให้ถูก ไม่ใช่จับผิด) และเริ่มแบบไม่บล็อกใครก่อน

## 9. เจ้าของต้องเตรียม / ตัดสินใจ

1. **พิกัดร้าน** (เปิด Google Maps ที่หน้าร้าน กดค้าง → คัดลอกเลข lat,lng) — ถ้ามีหลายจุด
   (หน้าร้าน + คลังสาย 5) ต้องได้ทั้ง 2 จุด และบอกว่าใครลงเวลาที่จุดไหนได้
2. **เวลาเข้า–เลิกงานจริงของแต่ละตำแหน่ง** + เวลาพัก + สายได้กี่นาทีถึงจะไม่นับสาย
3. มีกะเดียวหรือหลายกะ (เช้า/บ่าย) และมีคนทำงาน 6 วัน/สัปดาห์ไหม
4. อยากให้ **บล็อก** เมื่อลงเวลานอกพื้นที่ หรือแค่ **บันทึกว่าอยู่นอกพื้นที่** ให้เจ้าของเห็น
   *(แนะนำอย่างหลังในช่วง 2 สัปดาห์แรก)*
5. บังคับถ่ายรูปทุกครั้ง หรือเฉพาะตอน "เข้างาน"
6. ~~รายงานเงินเดือน~~ — **เจ้าของตัดสินแล้ว (2026-07-29): ไม่ทำถึงเงินเดือน**
   ระบบจบที่ "บันทึก + สรุปชั่วโมง/สาย/ขาด/ลา + ดาวน์โหลด CSV" เท่านั้น
   ไม่มีฐานเงินเดือน/OT rate/ประกันสังคมในระบบ — บัญชีเอา CSV ไปคิดต่อเอง

**นโยบายที่เจ้าของเลือก**
- **พัก**: ไม่กำหนดตายตัว — จับเวลาจริงจากปุ่ม "เริ่มพัก"/"กลับจากพัก" ของแต่ละคน
- **สาย**: ไม่มีผ่อนผัน เลยเวลาเริ่มกะ = สาย และบันทึกว่าสายกี่นาที
- **GPS นอกพื้นที่**: บันทึกอย่างเดียว **ไม่บล็อก** (ช่วง 2 สัปดาห์แรก เก็บสถิติก่อนตั้งรัศมีจริง)
- **รูปถ่าย**: บังคับเฉพาะตอน "เข้างาน" เท่านั้น

**สิ่งที่เบี่ยงจากแผนเดิม**
- **ยังไม่ทำ LIFF/Rich Menu** — ใช้แท็บ "⏱️ ลงเวลา" ในเว็บเดิมไปก่อน (พนักงานล็อกอิน LINE
  อยู่แล้วจึงรู้ว่าใครเป็นใคร) · LIFF + Rich Menu ค่อยเพิ่มทีหลังถ้าเจ้าของอยากให้กดจากแชทได้เลย
- **วันจันทร์หน้าร้านไม่มีในตารางกะ** (เจ้าของไม่ได้ระบุ) → ระบบถือว่า "ไม่มีกะ" = ลงเวลาได้ปกติ
  แต่ไม่คิดสาย · ถ้าจันทร์เปิดร้านจริง ให้เพิ่มแถวในชีต "ตั้งค่ากะ"
- **owner/saler ไม่มีกะ** ในตาราง → ลงเวลาได้ แต่ไม่คิดสาย (เพิ่มแถวเองได้ถ้าต้องการ)

- **ยังไม่มีลบรูปอัตโนมัติ 90 วัน** — ต้องทำใน trigger รอบหน้า
