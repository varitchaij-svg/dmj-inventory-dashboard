### 1.2 ล็อกอินเฟส 4 — `canDo_` + `REQUIRE_LOGIN` ✅ **ทำแล้ว (2026-07-30)**
> ลงจริงที่ `1c7caaf` + `bb54aed` + `71f2ead` · ชื่อฟังก์ชันจริงคือ `canDoOrNull_` (ไม่ใช่ `canDo_`)
> ดูรายละเอียดที่ `CLAUDE.md` หัวข้อ "ระบบล็อกอินพนักงาน" และ `PLAN-EMPLOYEE-LOGIN.md` ข้อ 5.1

> - `dmjFetch` (ui.jsx) แนบ `sessionToken` ให้ทุก POST อัตโนมัติ — ทำที่เดียวจบตามที่วางไว้
> - `IMMEDIATE_GATE_ACTIONS_` / `IMMEDIATE_GATE_STRICT_ACTIONS_` — 7 action ที่กระทบเงิน/สต็อก
>   บังคับสิทธิ์ทันทีไม่รอ `REQUIRE_LOGIN`
> - ✅ **เปิด `REQUIRE_LOGIN='true'` แล้ว (2026-07-30)** — พนักงานล็อกอิน LINE ครบทุกคน
>   เจ้าของรัน `enableRequireLogin()` เองใน GAS editor (เช็ค `lastLoginAt` ให้อัตโนมัติก่อนเปิด)
> - ⚠️ **เกือบพลาด**: `myAttendanceSummary` ("เวลาของฉัน" — ทุก role มี) กับ `attendanceToday`
>   (storedevice ใช้ดู "ใครเข้างานวันนี้") ไม่เคยผ่าน `canDoOrNull_` จริงมาก่อนเพราะ `REQUIRE_LOGIN`
>   ปิดอยู่ตลอด — พอจะเปิดจริงเจอว่า 2 action นี้ไม่อยู่ใน `ROLE_ACTIONS_` เลยสักตัว ถ้าเปิดตรงๆ
>   จะบล็อกพนักงานทุกคนออกจาก "เวลาของฉัน" ทันที + เครื่องร้านดู "ใครเข้างานวันนี้" ไม่ได้
>   แก้แล้วก่อนเปิดจริง (เพิ่มเข้า `ROLE_ACTIONS_` ทุก role ที่เกี่ยวข้อง) + เพิ่มเทสต์กันไว้ไม่ให้เกิดซ้ำ

ตราบใดที่ `actor` ยังมาจาก client **ตัวเลข "งานรายคน" ทุกตัวในข้อ 3 เชื่อไม่ได้**
และการเอาไปคุยกับพนักงานเรื่องผลงานจะไม่แฟร์
- ที่ `doPost`: `var sess = resolveSession_(ss, data.sessionToken)` → ถ้ามี ให้ **override** `actor`
  ด้วยชื่อจาก session (ห้ามเชื่อ `data.actor` อีก)
- `canDo_(role, action)` whitelist ฝั่ง server — ล้อ `ROLE_TABS`
- เปิด `REQUIRE_LOGIN='true'` **เฉพาะเมื่อ** `lastLoginAt` ในชีต `พนักงาน` ครบทุกคนแล้ว
- ต้องส่ง `sessionToken` ไปกับทุก write action → มีจุดเรียก API กระจายอยู่หลายไฟล์
  ทางที่ถูก: ทำ helper กลางตัวเดียวแล้วให้ทุกที่เรียกผ่าน (อย่าไล่แก้ทีละจุด)

## 3. Tier 2 — ของใหม่ที่ "เพิ่งทำได้" เพราะรู้ว่าใครเป็นใคร  ⭐

นี่คือส่วนที่ตอบคำถาม *"ได้ข้อมูลพนักงานครบแล้วทำอะไรต่อได้"* โดยตรง —
เรียงตาม **ประโยชน์ต่อแรง** ไม่ใช่ตามความยาก

### 3.1 🎯 "งานของฉัน" — เปลี่ยนลิสต์รวมเป็นงานรายคน *(คุ้มที่สุด)*
ตอนนี้ทุกหน้าเป็น "ลิสต์กลาง ใครทำก็ได้" → พนักงานที่ไม่ถนัดเทคต้องเดาเองว่าอะไรคืองานตัวเอง
พอมี staffId แล้ว มอบหมายงานได้:
- ล็อคที่ต้องนับวันนี้ (ต่อยอดคิว "ควรนับก่อน" ใน StockCountView) → มอบหมายรายคน
- order ที่ต้องจัด · งาน MTO ที่รับผิดชอบ · สินค้าหน้าร้านที่ต้องเช็ค
- หน้าแรกของ warehouse/frontstore = **"วันนี้คุณมี 5 งาน"** แทนแท็บว่าง ๆ
- ผลพลอยได้: เจ้าของเห็นว่างานค้างอยู่ที่ใคร ไม่ใช่ค้างลอย ๆ

**หมายเหตุ**: ต้องเพิ่มคอลัมน์ `ผู้รับผิดชอบ (staffId)` ในชีตงานที่เกี่ยว (order/MTO/คิวนับ)
เริ่มจาก **MTO ก่อน** เพราะมีโครงงานชัดที่สุดและปริมาณน้อย เห็นผลเร็ว

#### ✅ MTO ทำแล้ว (2026-07-30)
- ชีต "งาน MTO" เพิ่มคอลัมน์ I/J = `ผู้รับผิดชอบ(staffId)`/`ชื่อผู้รับผิดชอบ` (self-heal header
  ให้ชีตเก่าที่มีอยู่แล้วด้วย ไม่กระทบแถวข้อมูลเดิม)
- **default = คนสร้างงานเอง** (จาก session ที่ server ตรวจแล้ว ไม่ใช่ text ที่ client ส่งมา) —
  ตรงตามที่เจ้าของขอ "ขึ้นตามเครื่องที่เป็นคนสร้างเลย"
- เปลี่ยนผู้รับผิดชอบได้ทีหลัง — action ใหม่ `assignMtoJob` (warehouse/employee — role เดียวกับที่
  สร้าง/ปิดงาน MTO ได้อยู่แล้ว) + action ใหม่ `listActiveStaffNames` (ทุก role ที่ล็อกอินแล้วเรียกได้
  คืนแค่ staffId+name ไม่มีข้อมูลอ่อนไหว — ใช้เติมดรอปดาวน์เลือกคน ต่างจาก `listStaff` ที่ owner/dev
  เท่านั้นเห็นข้อมูลเต็ม)
- ตัวกรอง "🙋 งานของฉัน" ในลิสต์เดิม (ไม่ใช่แท็บใหม่) — ไม่ซ่อนงานจากใคร คนอื่นยังกดดูลิสต์เต็มได้
- **⚠️ พบช่องโหว่ระหว่างทาง ยังไม่ได้แก้**: `MtoJobView` ไม่ได้รับ prop `role` เลย (`app.jsx` เรียก
  `<MtoJobView data={data} />` เฉย ๆ) → ปุ่มสร้าง/ปิดงาน MTO โชว์ให้ **ทุก role ที่มีแท็บ "mtojobs"**
  เห็นเหมือนกันหมด (รวม frontstore/saler/storedevice) แต่ `ROLE_ACTIONS_` อนุญาตแค่
  warehouse/employee ให้ทำจริง — ตราบใดที่ `REQUIRE_LOGIN` ปิดอยู่ไม่มีผล แต่ตอนนี้เจ้าของเพิ่งเปิด
  `REQUIRE_LOGIN='true'` แล้ว → frontstore/saler/storedevice กดปุ่มเหล่านี้จะโดน "ไม่มีสิทธิ์" ทันที
  **ต้องถามเจ้าของก่อนว่า 3 role นี้ควรสร้าง/ปิดงาน MTO ได้จริงไหม หรือควรซ่อนปุ่มให้เหลือแค่ดู**
  ก่อนตัดสินใจแก้ฝั่งไหน (ยังไม่ได้ถาม ณ ตอนบันทึกนี้)

### 3.2 📲 แจ้งเตือน LINE รายบุคคล (แทน @All ทั้งกลุ่ม)
เรามี LINE userId ของทุกคนแล้วใน `พนักงาน` col C
- ส่งเฉพาะคนที่เกี่ยว: "ของที่คุณสั่งถึงแล้ว ไปรับที่หน้าร้าน", "งาน MTO ของคุณครบกำหนดพรุ่งนี้",
  "คุณลืมกดออกงานเมื่อวาน" — แทนที่จะยิง @All แล้วทุกคนเมิน
- ประหยัดโควตาด้วย: 1 ข้อความหา 1 คน แทน 1 ข้อความปลุกทั้งกลุ่ม
- ใช้คิวเดิม `enqueueNoti_` ได้เลย แค่ตั้ง `target` เป็น userId

> ⚠️ **ต้องทดสอบยืนยัน 1 ครั้งก่อน**: LINE userId จะตรงกันระหว่าง Login channel กับ Messaging API
> **ก็ต่อเมื่ออยู่ provider เดียวกัน** — แผนล็อกอินระบุว่าใช้ provider เดียวกับ OA แล้ว แต่ยังไม่เคยทดสอบส่งจริง
> วิธีทดสอบ: เอา `providerUserId` ของเจ้าของจากชีต ยิง push ผ่าน Messaging API 1 ครั้ง ถ้าเข้า = ใช้ได้ทั้งระบบ
> ถ้าไม่เข้า → พนักงานต้องกด follow OA แล้วเก็บ userId จาก webhook `follow` event แทน

### 3.3 👤 โปรไฟล์พนักงาน — "คนนี้ทำอะไรไปบ้าง"
ในแท็บ `staff` ที่มีอยู่แล้ว แตะการ์ดคน → เห็น:
- สรุปจาก Audit Log: นับสต็อกกี่ล็อค · โอนกี่ครั้ง · รับของกี่ครั้ง · ตรวจหน้าร้านกี่รอบ · ปิด MTO กี่งาน
- สรุปจากลงเวลา: มาทำงานกี่วัน สายกี่ครั้ง ชม.รวมเดือนนี้
- 20 action ล่าสุดของคนนี้
- **ทำได้เลยแทบไม่ต้องเขียน backend ใหม่** — แค่ filter Audit Log ตาม actor
  (แต่ตัวเลขจะเชื่อได้จริงหลัง Tier 0 ข้อ 1.2)

### 3.4 🔍 ตามรอยความผิดพลาดกลับไปหาต้นตอ
- สต็อกเพี้ยน/ของหาย → "ล็อคนี้ใครนับล่าสุด เมื่อไหร่" → สอนงานตรงจุด ไม่ใช่ประกาศรวม ๆ
- **ล็อคที่คนเดิมนับตลอด** → สลับคนนับ (best practice ของ cycle count — คนที่นับผิดประจำจะนับผิดซ้ำเดิม)
- ธง "ผลต่างการนับสูงผิดปกติ" รายคน → รู้ว่าใครต้องสอนเพิ่ม

### 3.5 📍 ค่าเริ่มต้นตามจุดประจำ
เพิ่มคอลัมน์ `ประจำจุด` (หน้าร้าน / คลังสาย5) ในชีต `พนักงาน` → ใช้ได้หลายที่ทันที:
- คนคลังเปิดแอปมาเห็นคลังเป็น default ไม่ต้องเลือกทุกครั้ง
- ลงเวลาเทียบระยะกับ **จุดของตัวเอง** (ตอนนี้เทียบจุดที่ใกล้ที่สุด — คนหน้าร้านไปคลังแล้วระบบไม่รู้ว่าผิดที่)
- คิว "ควรนับก่อน" / "ควรเช็คก่อน" กรองตามจุดของคนนั้น

### 3.6 💰 ยอดขายรายคน (saler)
ใบเสนอราคา/POS มี `actor` อยู่แล้ว → ผูกกับ staffId ได้:
- ใครขายได้เท่าไหร่เดือนนี้ · ใบเสนอราคาค้าง follow-up เป็นของใคร (QuoteFollowupView กรองรายคนได้)
- **ไม่ทำถึงค่าคอม** — จบที่ "เห็นตัวเลข" ตามขอบเขตที่เจ้าของตัดสินเรื่องเงินเดือนไว้แล้ว

เลิกจดใบลาในแชท · ผูกกับหน้า "ใครเข้างานวันนี้" ให้แยก **"ยังไม่มา"** ออกจาก **"ลา"** ได้

### 3.8 ⏱️ ชม.ทำงาน × ปริมาณงาน  *(ทำได้ แต่แนะนำให้ระวัง)*
พอมีทั้งชั่วโมงและจำนวนงาน คำนวณ "งาน/ชม." รายคนได้ทันที
**ข้อแนะนำตรง ๆ**: ใช้ดู **แนวโน้มของทีม** และหาจุดที่งานล้น อย่าเอาไป **จัดอันดับรายคน** —
งานคลังมีความยากไม่เท่ากัน (นับล็อคใหญ่ 200 ชิ้น กับล็อคเล็ก 5 ชิ้น นับเป็น 1 เท่ากัน)
ตัวเลขนี้จะดูเหมือนแฟร์แต่ไม่แฟร์ และเป็นเรื่องที่ทำลายความไว้ใจทีมได้เร็วที่สุดในบรรดาทุกฟีเจอร์ที่วางไว้

## 6. รอเจ้าของตัดสินใจ

1. **ทดสอบ LINE push รายบุคคล** — ต้องยืนยันว่า userId จาก Login ใช้กับ Messaging API ได้ไหม
   (ทดสอบ 5 นาที ตัดสินได้เลยว่าข้อ 3.2 ทำได้หรือต้องเปลี่ยนวิธี)
2. **"งานของฉัน" เริ่มจากงานไหน** — MTO / คิวนับสต็อก / order จัดของ (แนะนำ MTO)
3. **จะเอาข้อมูลลงเวลาไปใช้ยังไง** — แค่บันทึกไว้เผื่อมีปัญหา / ส่งบัญชี CSV ทุกเดือน /
   คุยกับพนักงานเรื่องสาย · คำตอบเปลี่ยนว่าเฟส C ต้องละเอียดแค่ไหน
4. **บอกทีมหรือยัง** ว่าระบบเก็บพิกัด+รูป — ถ้ายัง ควรบอกก่อนที่จะมีคนไปเห็นเอง
   (PDPA + เรื่องความรู้สึก · แผนลงเวลาข้อ 7.5/7.7)
5. **วันจันทร์หน้าร้านเปิดไหม** — ยังไม่มีในชีต `ตั้งค่ากะ` ระบบถือว่า "ไม่มีกะ" = ไม่คิดสาย
